# Bounded halfword switch recovery

Xenon360 0.8.2 extends the existing `Xenon360 Bounded Switch Tables` analyzer. Install the extension, import an Xbox 360 executable, and run normal Ghidra analysis. No additional script, SDK, or modified Ghidra installation is required. The processor language remains revision 1.1, preserving the 0.8.1 VMX128 fixes.

Compatibility was checked against stock Ghidra 12.2 and public upstream reports, including [issue 8963](https://github.com/NationalSecurityAgency/ghidra/issues/8963) and [PR 8964](https://github.com/NationalSecurityAgency/ghidra/pull/8964). Xenon360's fallback remains independent, does not modify installed Ghidra, and does not transplant third-party fork or manual-script implementations.

The fallback accepts an unsigned `cmplwi cr6` bound, `bgt cr6`, a proven index-times-two operation, explicit `lis/addi` addresses, `lhzx`, an addition to a constant code base, and `mtctr/bctr`. The two validated load-address/index orders and optional pre-branch NOP are supported. Up to four non-updating stack stores may separate the compare and guard. Entry zero is a valid relative offset. Signed address-low immediates are decoded from instruction words rather than mnemonic aliases.

Each table has at most 512 entries in one initialized, read-only, non-executable block. Every destination must be aligned and in the same executable block. The analyzer rejects conflicting flow references, entry into a dispatch after its guard, other function owners, manually named functions, user/imported symbols in newly reached code, defined data, and unsupported computed jumps. It proves at most 64 KiB of additional code and 32 nested supported tables before mutation. It creates no functions, deletes no references, and assigns no symbols. Existing byte-table recovery is retained.

The analyzer's transaction covers disassembly, references, function-body extension and evidence. Cancellation or failure rolls these changes back. Proven direct calls into undefined executable code receive a separate preflight limited to 16 entries and 4 KiB; those instructions are kept outside the caller body. Recovered instructions are submitted to ordinary Ghidra analysis for function/call discovery and constant propagation. A repeated invocation adds no duplicate edges. The fallback runs before initial stack-variable analysis and does not force replacement of an existing project's stack variables.

Portable synthetic fixtures exercise guarded table indices, out-of-range conditions, nested dispatches, rollback, and repeatability. After the fallback restores validated edges, ordinary Ghidra analysis may discover further calls or functions. No private binary case studies, addresses, hashes, or reconstruction procedures are published or required by the extension.

`XenonHalfwordSwitchTest.java` tests supported forms, zero offsets, nested recovery, existing instruction prefixes, ownership, manual symbols, bad guards, bad targets, partial selections, budgets, cancellation during mutation, and idempotency. It runs alongside the existing standalone, VMX128, analyzer-safety and byte-switch suites in `smokeTest`. Corpus qualification and visual acceptance are separate gates; a successful build alone is not release qualification.

Generic multi-block predecessor traversal, signed-relative tables, writable jump tables and speculative callback/vtable classification remain unsupported by this fallback. Stock Ghidra analyzers continue to handle their own supported patterns. Public reference source and proprietary corpus inputs are not included in the extension ZIP.
